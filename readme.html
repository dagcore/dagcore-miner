1

What you need

  • A BlockDAG wallet address — 0x followed by 40 hexadecimal characters. It is where the pool pays; there is no account to create.
  • An NVIDIA graphics card with the NVIDIA driver installed. The miner talks to the card through the driver's OpenCL; nothing else has to be installed for it. nvidia-smi, which comes with the driver, is what the power and clock controls use.
  • Linux on x86-64 — the supported system, with an installer and a service. Windows 10 (1803 or later) works for testing.
Windows is experimental. The Windows build runs by hand and has no installer or service. Clock locks and offsets are Linux-only for now (the Windows build has no NVML); the power limit goes through nvidia-smi as on Linux but has not been tried on Windows, where changing it may need the miner started as administrator. Mining itself works the same.

2

Put the miner in place

Linux

Get the source and run the installer. It checks the machine, offers to install what it needs to build, compiles, and sets everything up:

git clone https://github.com/dagcore/dagcore-miner.git
cd dagcore-miner
sudo ./install.sh

To see what it would do without touching anything: ./install.sh --dry-run.

The program goes to /opt/dagcore-miner/, the configuration to /etc/dagcore-miner/config.env.

Windows test

Copy the whole DAGCore folder somewhere you can write to, for example C:\DAGCore — not Program Files: the miner keeps its settings in that same folder and has to be able to save them.

Inside it you have:

  • dagcore-miner.exe — graphics card (and CPU)
  • dagcore-miner-cpu.exe — CPU only
  • dagcore_gpu.cl — the card's program; keep it next to the .exe
  • dashboard\ — the web page
  • config.env.example
  • this page

Nothing to install: the .exe brings no DLLs of its own.

3

Set your wallet

Linux

The installer asks for it, and checks it: 0x plus 40 hexadecimal characters. It then asks a few more things; the defaults are right for most rigs:

QuestionDefault
Pool and portstratum.dagcore.net, 3334
CPU mining threads0 — card only; the CPU adds under 1%
Which cardsall of them (asked only with more than one)
Dashboard from this machine onlyyes
Create a service, start nowyes, yes

For many machines at once: sudo ./install.sh --wallet 0xYOURADDRESS --yes.

Windows

Rename config.env.example to config.env, open it in Notepad and replace the placeholder on the WALLET= line:

WALLET=0xYOURADDRESS

That is the only line you must change. Everything else in the file is explained where it stands, and can wait for the dashboard.

For the CPU-only .exe, also set THREADS=-1 (half the cores); left at 0 it warns and does that anyway.

Check the address twice. A typo mines for somebody else, and nothing can undo that. The dashboard asks for confirmation before it changes the wallet, for the same reason.

4

Start mining

Linux

With the defaults the installer has already started it, as the dagcore-miner service: it starts at boot and restarts by itself.

sudo systemctl status dagcore-miner     # running?
sudo journalctl -u dagcore-miner -f     # its log, live
sudo systemctl restart dagcore-miner

Without a service (a container, or you said no): sudo /opt/dagcore-miner/start.sh, Ctrl+C to stop.

Windows

Double-click dagcore-miner.exe (or dagcore-miner-cpu.exe on a machine without an NVIDIA card). A console window opens and stays open while it mines. Windows may ask whether to allow network access the first time — allow it.

To stop: Ctrl+C in that window, or close it. Either way the miner shuts down cleanly.

It finds everything in its own folder, whichever folder it is started from.

How to tell it worked: the log shows Connected!, then Authorized and Mining started!, and soon lines with Share ACCEPTED. In the first seconds they come fast — the pool starts every connection at a low difficulty and raises it over the first minutes.

5

Open the dashboard

In a browser on the same machine: http://localhost:8881/. It shows the hashrate, the shares, the card's temperature and power, a 30-minute chart, and the settings. Reading it needs nothing else.

From another computer

By default the dashboard answers only on the machine itself. The safe way to reach it from elsewhere is an SSH tunnel, then open the same address:

ssh -L 8881:127.0.0.1:8881 user@rig-address

Opening it to the whole local network (--lan for the installer, METRICS_BIND=0.0.0.0 in config.env) works too, but then everyone on that network sees the page, including your full wallet address.

6

Enter the control token

Changing anything from the dashboard needs the rig's control token, a long random string the miner creates the first time it starts. Paste it once under Settings → Control token and press Save; the browser keeps it.

Linux

sudo cat /etc/dagcore-miner/api-token

It is also printed once, on the first start, in the log.

Windows

The file api-token in the miner's folder — open it with Notepad. The first start also prints it in the console, after Token:. Every start names the file it uses (Control API token:).

How to tell it worked: the controls in Settings stop being greyed out. Rejected: invalid token means it was mistyped, or a new one was made since — delete the file and restart the miner to get a fresh one.

7

Mining configuration

At the top of Settings, in its own box: wallet, pool and port, CPU threads and graphics cards. The same settings as in config.env; saving writes them there and keeps the previous file as config.env.bak.

  1. Change what you want — any number of fields.
  2. The box turns orange and says what is not saved yet:
    CPU threads3
    Not saved yet: CPU threads 2 → 3. Press Save & restart to apply.Save & restart
  3. Press Save & restart at the bottom of that box. The miner restarts to apply it, and the page reconnects by itself.
Two buttons read "Save & restart". The one inside the Mining configuration box saves the box. The one next to GPU intensity saves the intensity only — if the box has unsaved changes, it asks first.

CPU threads: auto is half the logical cores, 0 is card only. Under the setting the page shows what the CPU is adding right now — on a rig with a card, well under one percent, which is why the default is 0.

A field marked set on the command line cannot be changed here: the command line wins over config.env at every start.

8

Tune the card optional

The rest of Settings. None of it is needed to mine; it trades power and heat for hashrate. Change one thing at a time — if two change together and shares start being rejected, there is no telling which one did it.

SettingWhat it doesHow it applies
GPU power limitCaps the card's watts. Lower saves power and heat, usually for little hashrate.Apply — at once
Memory offsetRaises the memory clock; this algorithm is memory-bound, so this is where hashrate comes from. Apply — then a 10-minute test
GPU intensityHow much work each batch gives the card, 0–100. Lower leaves the machine more responsive.Save & restart
Advanced: core clock, memory clock, core offsetFor experienced users.Apply — then a 10-minute test

The 10-minute test starts by itself for clock changes. A banner shows the countdown and the rejected shares. If any appear, the old value comes back on its own and nothing is saved; after ten clean minutes the new one is kept for every future start. You do not have to keep the page open.

Default on each row gives the card's own factory value back.

9

Check that it works

  • The chip at the top says mining (not connecting or paused).
  • GPU hashrate is steady — an RTX 3080 does about 1.6 MH/s. A card missing from the count, or a GPU figure of 0 with only CPU mining, is not normal: see below.
  • Accepted shares keep rising; rejected stays at or near 0. A few stale ones are normal.
  • Effective hashrate — what the pool actually credited — appears after ten minutes and settles near the raw figure. In the first minutes after a start it runs low while the pool's difficulty climbs; that is expected.
That is all. From here the rig mines on its own. Pause mining in the header stops it without closing anything; the page stays up so you can resume from it.

Upgrading

Linux

cd dagcore-miner
git pull
sudo ./install.sh        # choose Upgrade

Settings are kept. What changed is in CHANGELOG.md.

Windows

Stop the miner, then copy the new .exe files, dagcore_gpu.cl, the dashboard folder and this page over the old ones. Keep config.env, api-token and overrides.env: they hold your settings and the token your browser knows.

When something is wrong

You seeWhat to do
The dashboard does not open Is the miner running (step 4)? Is it the same machine, or a tunnel (step 5)? The log says Metrics server on http://… with the address it answers on.
GPU 0 H/s, only the CPU mining The miner found no card. Check the NVIDIA driver; in a container, the installer offers the missing OpenCL registration — say yes.
Controls greyed out No token in this browser — step 6. On a rig with several cards, or without nvidia-smi, the reason is written on each control.
A change "does nothing" In Mining configuration, was the box saved with its own Save & restart (step 7)? Is the field set on the command line?
Rejected shares after tuning Let the 10-minute test put the old value back, or press Cancel test. Then try a smaller step.
Windows: nothing saved, token missing The folder must be writable — not Program Files. The console names the files it uses at every start.

Every number and every message on the dashboard is explained in Help (the miner has to be running), and installation in more depth in docs/INSTALL.md of the source.
